# Rotno Photo Studio (Next.js + MongoDB)

প্রিমিয়াম 4K ব্যাকগ্রাউন্ড জেনারেটর। **Firebase নেই**: backend পুরোটা Next.js API routes, ডাটাবেস MongoDB।
ছবি তৈরি হয় ইউজারের ব্রাউজারে; লগইন, প্ল্যান, ট্রায়াল গণনা, পেমেন্ট ও অ্যাডমিন সবকিছু সার্ভারে যাচাই হয়।

## ফিচার
- ৮টা স্টাইলের জেনারেটর, ১০টা প্যালেট + কাস্টম/র‍্যান্ডম রঙ, সিড; HTML → ছবি (4K/8K পর্যন্ত)
- নিজস্ব লগইন: ইমেইল + পাসওয়ার্ড (bcrypt), httpOnly কুকি সেশন (JWT), ৫ বার ভুলে ১০ মিনিট লক
- 720p ফ্রি, তার উপরে ফ্রি ট্রায়াল (সার্ভারে গোনা হয়), তারপর Pro
- বিকাশ ম্যানুয়াল পেমেন্ট (TrxID), অ্যাডমিন অনুমোদন করলে Pro (পরপর কিনলে মেয়াদ যোগ হয়)
- অ্যাডমিন প্যানেল: পেমেন্ট, ইউজার (Pro/Free/ব্যান/দিন যোগ/পাসওয়ার্ড রিসেট), সাইট সেটিংস, প্ল্যান ও টুলস এডিটর

## ১. MongoDB (একবার)
1. [MongoDB Atlas](https://www.mongodb.com/atlas)-এ ফ্রি cluster বানান (বা লোকাল MongoDB)।
2. Database Access → একজন ইউজার + পাসওয়ার্ড বানান।
3. Network Access → Vercel ব্যবহার করলে `0.0.0.0/0` যোগ করুন (Vercel-এর IP স্থির না)।
4. Connect → Drivers থেকে connection string কপি করুন।

## ২. চালানো
```bash
npm install
cp .env.local.example .env.local   # MONGODB_URI আর AUTH_SECRET বসান
npm run dev                         # http://localhost:3000
```
`AUTH_SECRET` বানাতে: `openssl rand -base64 48`

## ৩. অ্যাডমিন বানানো
সাইনআপ ফর্ম দিয়ে কেউ অ্যাডমিন হতে পারে না (ইচ্ছাকৃত)। নিজে প্রথমে সাইটে সাইনআপ করুন, তারপর:
```bash
npm run make-admin -- you@example.com
```
এরপর লগআউট করে আবার লগইন করুন, নিচের ট্যাবে 🛠 অ্যাডমিন আসবে। Production DB-তে করতে চাইলে `.env.local`-এ production-এর `MONGODB_URI` দিয়ে কমান্ডটা একবার চালান। অ্যাডমিন থেকে অন্য ইউজারদের ম্যানেজ করা যায়।

## ৪. Vercel-এ deploy
1. GitHub-এ push করুন (`.env.local` push হয় না)।
2. Vercel → Import → Environment Variables: `MONGODB_URI`, `MONGODB_DB` (ঐচ্ছিক, ডিফল্ট `rotno_photo`), `AUTH_SECRET` → Deploy।
3. সাইটে সাইনআপ করে `npm run make-admin` চালান।

## Environment variables
| নাম | কাজ |
|-----|-----|
| `MONGODB_URI` | MongoDB connection string |
| `MONGODB_DB` | ডাটাবেসের নাম (ডিফল্ট `rotno_photo`) |
| `AUTH_SECRET` | সেশন সই করার গোপন কী (≥ ৩২ অক্ষর)। বদলালে সবাই লগআউট হবে |

## ডাটাবেস collection
`users`, `payments`, `settings` (`_id: "public"`)। ইনডেক্স নিজে তৈরি হয় (ইউনিক ইমেইল, ইউনিক TrxID)।

## API (সব `src` ছাড়া, `app/api/...`)
| রুট | কাজ |
|-----|-----|
| `GET /api/settings` | পাবলিক সেটিংস (প্ল্যান, বিকাশ নম্বর, নোটিশ) |
| `POST /api/auth/signup`, `login`, `logout`; `GET /api/auth/me` | লগইন সিস্টেম |
| `POST /api/usage/consume` | ছবি তৈরির আগে সার্ভারে অনুমতি + ট্রায়াল গণনা |
| `GET/POST /api/payments` | নিজের পেমেন্ট / নতুন অনুরোধ (দাম ও দিন সার্ভার প্ল্যান থেকে নেয়) |
| `GET /api/admin/payments`, `POST /api/admin/payments/[id]` | অ্যাডমিন: তালিকা, approve/reject |
| `GET /api/admin/users`, `PATCH /api/admin/users/[id]` | অ্যাডমিন: ইউজার ম্যানেজ |
| `PUT /api/admin/settings` | অ্যাডমিন: সেটিংস সেভ |

## নিরাপত্তা যা করা আছে
- পাসওয়ার্ড bcrypt হ্যাশ; কুকি `httpOnly` + `SameSite=Lax` (+ production-এ `Secure`); অন্য সাইট থেকে আসা POST আটকানো হয় (Origin চেক)
- রোল ও প্ল্যান শুধু সার্ভার/DB-তে; সাইনআপে কেউ admin/pro নিজে সেট করতে পারে না
- পেমেন্টে TrxID ইউনিক, দাম/দিন ক্লায়েন্ট থেকে নেওয়া হয় না, অনুমোদন একবারই কাজ করে
- ট্রায়াল গণনা অ্যাটমিক (একসাথে অনেক রিকোয়েস্টেও সীমা পেরোয় না)
- ব্যান করলে সেশন সাথে সাথে অচল; পাসওয়ার্ড রিসেটে পুরোনো সেশন বন্ধ; অ্যাডমিন সেটিংসে URL/সাইজ যাচাই

## সীমাবদ্ধতা
- ছবি তৈরি ব্রাউজারেই হয়, তাই কেউ JS বদলে সার্ভারের অনুমতি ছাড়াই 4K ছবি আঁকতে পারে। সার্ভার শুধু অ্যাকাউন্ট, প্ল্যান ও পেমেন্ট নিয়ন্ত্রণ করে; ছবি-আঁকা পুরোপুরি আটকাতে হলে রেন্ডার সার্ভারে নিতে হবে (খরচ ও গতি বাড়বে)।
- ইমেইল পাঠানোর ব্যবস্থা নেই: পাসওয়ার্ড ভুলে গেলে ইউজার WhatsApp-এ জানাবে, অ্যাডমিন প্যানেল থেকে অস্থায়ী পাসওয়ার্ড দেবেন। ইমেইল ভেরিফিকেশনও নেই।
- বিকাশ পেমেন্ট ম্যানুয়াল: TrxID সত্যি কিনা অ্যাডমিন বিকাশ অ্যাপে মিলিয়ে অনুমোদন দেবেন।
- লগইন লক ডাটাবেসে রাখা হয় (প্রতি ইমেইলে)। আরও কড়া চাইলে Vercel Firewall/Upstash রেট-লিমিট যোগ করুন।
